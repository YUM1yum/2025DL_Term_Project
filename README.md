# You Only Look UI

웹과 앱 화면에서 YOLOv8로 아이콘을 찾고, 탐지한 영역을 잘라 BLIP로 설명을 생성하는 딥러닝 프로젝트입니다. 실제 화면에서는 글자, 로고, 삽화도 아이콘처럼 보입니다. 이 프로젝트에서는 이런 요소를 학습 데이터에 어떻게 반영해야 오탐을 줄일 수 있는지 실험했습니다.

[발표 슬라이드](./발표용_slides.pdf) · [데이터셋](./dataset/)

## 아이콘 탐지 실험

1280×720 배경에 아이콘과 비대상 요소(`others`)를 합성하고 위치 라벨을 생성했습니다. 아이콘은 약 70%를 줄지어 배치하고 나머지는 무작위로 배치했습니다. 회전, 블러, 투명도를 조정하고 아이콘이 없거나 매우 작은 화면도 포함했습니다. YOLOv8s를 단순한 배경부터 학습시킨 뒤 이전 단계의 가중치로 다음 단계를 시작했습니다.

| 실험 | 학습 데이터와 방법 | Precision | mAP@50 |
| --- | --- | ---: | ---: |
| 1차 | 기본 합성 데이터, 아이콘 단일 클래스 | 0.243 | 0.129 |
| 2차 | 비대상 클래스 추가, 도형 합성 | 0.142 | 0.098 |
| 3차 | 배경·아이콘 다양화, 순차 학습 | 약 0.39 | 약 0.20 |
| **4차** | **실제 UI의 비대상 요소를 CVAT으로 라벨링, 5단계 학습** | **0.476** | **0.358** |
| 5차 | 노이즈·색상·경계 변형 추가, 9단계 학습 | 약 0.35 | 약 0.26 |

발표 자료에서 가장 높은 탐지 성능을 기록한 구성은 4차였습니다. 2차에서 비대상 클래스를 추가했을 때는 두 지표가 모두 하락했고, 실제 화면에서 혼동되는 요소를 직접 라벨링한 4차에서 가장 높았습니다. 각 차수에서 여러 조건이 함께 바뀌었으므로 라벨링만의 효과를 이 수치로 분리하기는 어렵습니다.

## 아이콘 설명 생성

사전 학습된 BLIP는 검색 아이콘을 *a magnifying glass*, 설정 아이콘을 *a gear icon*으로 묘사했습니다. 돋보기 모양을 알아보는 것과 해당 버튼을 누르면 검색창이 열린다고 설명하는 것은 서로 다른 평가 과제입니다. 기준 설명과 비교한 결과는 BERTScore F1 약 0.83, BLEU 0.0000, METEOR 0.0089, ROUGE-L 0.0109였습니다.

## 노트북과 실행 방법

| 노트북 | 내용 |
| --- | --- |
| [5단계 순차 학습](./DL_1조_5단계_순차학습%26others_보강.ipynb) | 합성 이미지·라벨 생성, 비대상 요소 보강, YOLOv8 학습 및 평가 |
| [9단계 순차 학습](./DL_1조_9단계_순차학습.ipynb) | 노이즈와 시각적 변형을 추가한 확장 실험 |
| [아이콘 설명 생성](./DL_1조_Description.ipynb) | BLIP 캡션 생성 및 기준 설명과의 비교 |

1. 원하는 노트북을 Google Colab에서 열고 GPU 런타임을 선택합니다.
2. 탐지 실험에는 `dataset/icon_3.zip`, `dataset/others.zip`과 `dataset/backgound/`의 배경·라벨을 사용합니다. ZIP 파일을 풀고 노트북의 입력 경로와 파일명을 맞춥니다. `backgound`는 저장소에 등록된 폴더명입니다.
3. 합성 데이터 생성 셀을 실행한 뒤 학습·검증 이미지 경로를 각각 지정합니다. 단계별 학습이 끝나면 평가할 단계의 `best.pt`를 선택합니다.

**재현 시 확인할 점**

- 5단계 노트북은 기본 설정에서 학습과 검증에 같은 이미지 경로를 사용합니다. 독립적인 검증 결과를 얻으려면 검증용 이미지를 분리해야 합니다.
- 9단계 노트북의 마지막 평가 셀은 4단계 가중치를 불러옵니다. 9단계 결과를 평가하려면 체크포인트 경로를 변경해야 합니다.
- `syn_data_일부.zip`은 학습에 사용한 합성 데이터의 샘플입니다. 발표 결과를 재현하려면 전체 테스트 세트와 학습 가중치가 필요합니다. 캡셔닝 평가에 필요한 `images.zip`, `labels.zip`, `labels_des.zip`도 별도로 준비해야 합니다.
